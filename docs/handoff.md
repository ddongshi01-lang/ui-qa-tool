# 当前交接

## 项目现状

- 当前稳定版本为 `1.1.5`。
- 代码主入口仍然集中在单文件 `visual-qa.js`，没有拆模块和构建流程。
- 发布目录固定为 `dist/visual-qa-release/`，发布内容与根目录源码应保持一致。

## 主链路

- `service_worker.js` 负责点击扩展图标后的脚本注入、草稿存储、截图与下载。
- `content-bridge.js` 负责页面与扩展运行态之间的数据桥接。
- `visual-qa.js` 负责 hover、selected panel、measure、记录、AI 修改列表和 HTML 导出。

## 存储与权限

- 正式记录元数据、记录截图和 `noteImages` 由 `service_worker.js` 写入 IndexedDB 数据库 `pixel-audit-records`；旧版 `chrome.storage.local` 草稿会在读取时迁移。
- AI 修改列表仍由页面侧 `window.localStorage` 保存，与正式记录草稿互相独立。
- 导出 HTML 中的问题备注与完成状态使用报告所在浏览器的 `localStorage`，反馈截图使用 IndexedDB；“导出反馈版 HTML”会把反馈内容固化进文件。
- `unlimitedStorage` 用于避免记录截图、设计参考图和反馈图片因默认本地存储额度不足而丢失；数据不上传服务器。
- 调整扩展权限时，要同步维护 `store-listing/` 下的权限说明和隐私政策。

## 稳定区

- 选择模式主流程
- selected panel 编辑主流程
- 测量模式主状态机
- 记录抽屉与记录保存
- 草稿恢复
- HTML 导出

这些区域默认按“局部修复优先”处理，不建议没有明确收益就做结构性重写。

## 近期新增约束

### 文本编辑态保持

- 文本元素被选中后，即使把文本内容清空，selected panel 仍要保留文本输入框。
- 当前元素仍应保持选中高亮或可编辑状态。
- 在空文本框重新输入内容时，仍要写回原来的文本元素。
- 这个保持逻辑只适用于“先前已被稳定识别为文本可编辑”的元素，不能把普通空 `div / card` 误识别成文本元素。

### 双元素测量结果工具条

- 仅在 `measureA / measureB` 锁定且存在有效间距时显示；“关闭测量”只清空 A/B，保留测量模式。
- 按钮继续使用 `data-vqa-measure-action` 进入既有记录/关闭处理；不要在鼠标移动时无条件重建其 DOM，否则 hover 会闪断。

### 导出 HTML 完成态

- 每条导出记录都有“已完成”复选框；勾选后卡片只显示绿色边框，按钮变为绿色实心状态，截图和详情同步弱化。
- 完成态由导出 HTML 内的 CSS `:has()` 响应复选框，不写回插件草稿；会与问题备注一起自动保存在当前浏览器。

### 导出 HTML 问题备注

- 原记录备注在报告中以只读“问题说明”展示，每条问题另有独立的可编辑“问题备注”。
- 问题备注用于开发填写处理情况、待确认事项或回复，不回写插件草稿。
- “下载反馈版 HTML”会把当前问题备注和完成状态写入新文件，便于回传并继续编辑。
- 问题备注输入框支持直接粘贴截图；每条最多 3 张，支持缩略图、原图预览和删除。
- 反馈截图会压缩并嵌入反馈版 HTML，图片暂存使用 IndexedDB，不能写入时提示用户下载反馈版保存。

### 记录问题说明截图

- 新增记录面板的问题说明输入框支持直接粘贴图片，每条记录最多 3 张。
- 图片压缩完成前禁止保存；完成后缩略图可在面板中删除。
- 图片保存在记录的 `noteImages` 字段中，草稿恢复后保留，并作为“设计参考截图”导出到 HTML。
- 保存后的说明截图在记录抽屉卡片中以“设计参考”缩略图展示。
- 记录面板打开或输入框聚焦时，`Command/Ctrl + V` 等系统组合键必须优先于插件的单字母模式快捷键。
